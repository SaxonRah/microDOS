# Native v2 Phase 3Q — bounded byte scanner/copy loops

Phase 3Q moves Native-v2 from benchmark-specific REP acceleration into a
common DOS/COMMAND.COM byte-string idiom.

The first production shape is:

```asm
header:
    lodsb
    cmp  al, delimiter
    je   done
    stosb
    loop header
done:
```

The measured instance appears at `9D1F:12B5` in the remaining-work profile:

```text
AC 3C 20 74 03 AA E2 F8
```

This is compiled as a 142-byte helper-free Thumb-2 region (`phase=14`).

## Safety / correctness proof

* `CX` is the hard maximum iteration count. Phase 3Q intentionally leaves the
  architectural `CX=0 -> 65536 iterations` case in fallback for now.
* `DF` must be clear.
* `DS:SI + CX` and `ES:DI + CX` must not wrap their 16-bit offsets.
* `DS` and `ES` must both be at or below `EFFFh`, avoiding 20-bit physical
  wrap for direct byte accesses. `DS` and `ES` do not have to be equal.
* The conservative full destination span `[ES:DI, ES:DI+CX)` is rejected if it
  overlaps the guest bytes currently executing natively.
* Future compiled regions remain protected by Native-v2's byte-for-byte
  validation on every re-entry.
* No C semantics helper is called from the generated byte loop.

## Exact retirement

The loop has two exits, so fixed `iterations * 5` accounting would be wrong.
The native return tag distinguishes them:

* tag 0: `LOOP` exhausted CX — 5 guest instructions per completed iteration.
* tag 1: delimiter `JE` exited before `STOSB/LOOP` — 5 per previous iteration
  plus `LODSB + CMP + JE` (3 instructions) for the final delimiter byte.

Runtime combines that tag with initial/final CX to retire the exact x86
instruction count.

## FLAGS

Both exits preserve the flags produced by the final `CMP AL,delimiter`.
Phase 3Q reconstructs canonical `MD_LAZY_SUB8` state after native return.
`LODSB`, `STOSB`, and `LOOP` do not alter those flags.

## Phase 3P baseline

Validated Pico result before Phase 3Q:

```text
19,200,000 instructions
active 0.788 s
24.353 MIPS
native-v2 17,578,810 (91.6%)
interpreted 1,621,190 (8.4%)
```

All hard invariants remained clean: DOS2TEST 25/25, MDSTRESS `0xA298`, 129
disk writes, and zero store/stack/muldiv/stale/runtime failures.
